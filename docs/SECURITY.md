# 安全设计基线

## 1. 身份、会话与权限

- 管理员账号通过一次性 CLI/受控初始化创建，不提供默认密码。
- 密码使用 Argon2id，记录参数/版本；登录失败计数、短期锁定、登录/重置限流。
- HttpOnly、Secure、SameSite 合理配置的服务端会话 Cookie；登录后轮换会话 ID，登出/改密/禁用账号撤销会话；token 只存哈希。
- 重置 token 一次性、短期有效、只存哈希；生产建议 TOTP/WebAuthn，MVP 数据模型预留。
- editor/reviewer/admin 权限按最小权限检查；editor 不能审核自己的提交，不能提升权限；每次授权失败也可按策略记录审计。

## 2. 输入、输出与浏览器安全

所有 Route Handler、Server Action、Worker 消息和导入行都做服务端 Zod/等价 schema、长度、格式、权限和未知字段拒绝。Markdown/HTML 采用允许列表清洗；React 转义不是富文本安全的替代。

设置 CSP、HSTS、`X-Content-Type-Options: nosniff`、`Referrer-Policy`、Permissions Policy、点击劫持防护和安全 Cookie。错误响应只给请求 ID 与安全错误码，不泄露堆栈、SQL、文件路径、密钥或内部拓扑。

## 3. SSRF 与开放重定向

这是最高优先级风险。所有外部 URL 使用标准 URL 解析器、HTTPS/允许域名列表、无用户信息段/非标准端口/IP 字面量/localhost/私网/保留地址；解析和实际请求都校验 DNS 解析 IP，防 DNS rebinding。通用外链限制重定向次数、总超时、响应体大小和内容类型，并禁止下载/执行响应体。

`/go` 只接受格式化的资源/平台/渠道 ID，从数据库读取已审核记录构造 URL；不接受任意目标 URL，不回退到 `Referer` 或请求参数。覆盖 IPv4/IPv6、十进制/八进制 IP、混淆域名、多层重定向、危险协议等专项测试。

## 4. 密钥、敏感字段与上传

仓库只提交无真实值的 `.env.example`；禁止 Cookie、Token、网盘账号、推广密钥、数据库密码、会话密钥、管理员密码、对象存储密钥和生产数据。服务端变量不得使用 `NEXT_PUBLIC_`。密钥轮换、启动校验、最小权限和分环境配置写入运维文档。

上传检查 MIME、扩展名、文件签名、大小、随机对象名和病毒扫描状态；证据私有存储。封面优先受控上传或允许域名代理，远程图片同样执行 SSRF 防护。

提取码单独字段保存，必要时应用层加密；日志、分析、错误和客户端包不得包含明文。无法合规验证提取码时只返回 `need_password`/`unknown`，不声称已验证。

## 5. 限流、日志与隐私

搜索、点击、提交、举报、侵权通知、登录、重置、导入分别限流；CSRF 防护、机器人防护和幂等键覆盖写接口。可信代理层级固定，不能盲信客户端 `X-Forwarded-For`。

日志为结构化 JSON，包含 request ID、事件类型、耗时、结果和脱敏错误分类；不写提取码、证据、投诉材料、密钥、完整 IP、完整 UA 或 Referer 查询内容。安全限流如需标识，使用轮换密钥 HMAC + 短 TTL。原始搜索/点击事件默认 90 天。

## 6. 依赖、容器与 CI

CI 包含 lint、类型检查、单元/集成/E2E（可用 mock 的外部服务）、依赖漏洞检查、secret scanning、CodeQL/静态检查和容器扫描。锁定 pnpm/Node/基础镜像版本，不用浮动 `latest`。Docker 使用非 root 用户、最小镜像、内部网络和可行的只读文件系统。

## 7. 备份、事件响应与验证

备份加密、访问最小化、每日执行；记录 RPO 24h/RTO 4h 目标，完成恢复演练后才宣称达成。安全事件流程：发现 -> 隔离/降权 -> 保全日志和证据 -> 评估影响 -> 修复/轮换 -> 通知与复盘。漏洞通过 `SECURITY.md` 私下报告，不要求公开敏感细节。

阶段四必须验证：SSRF/重定向、CSRF、XSS、越权、限流、敏感数据泄露、恶意 Markdown/CSV、重放回调、审计不可篡改、备份恢复；无法运行的检查标记“未运行”并记录原因和命令。
