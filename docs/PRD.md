# 网盘资料搜索与分发平台产品需求

> 文档版本：`0.2.0-architecture-approved`

## 1. 文档状态

- 阶段：阶段一（需求与架构）
- 版本：0.2.0-architecture-approved
- 事实基线：用户提供的《网盘资料搜索与分发平台：完整项目需求与执行指令（修订版）》
- MVP 目标：可自托管、可审计、合规优先的本地授权资料搜索与安全跳转平台
- 本文不授权进入阶段二；代码、迁移和部署脚手架待用户确认后实施。

## 2. 产品定位与非目标

平台只索引部署者拥有完整权利、获得明确授权、使用允许再分发的开放许可、进入公有领域，或经审核确认具有分享权限的资料。平台保存资料元数据和受控网盘链接，不下载、转存、重新上传或代理第三方内容。

明确非目标：全网盗版搜索、第三方盘搜站/搜索引擎爬取、登录后内容抓取、破解或逆向网盘接口、自动转存下载、盗版影视/课程/软件、账号与泄露数据聚合、面向公众的账号/社交/推荐画像系统。

## 3. 角色与权限摘要

| 角色     | 可做                                                                                                      | 不可做                                                      |
| -------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| visitor  | 搜索、查看公开资源、前往网盘、提交资料/举报/侵权通知、查询工单状态                                        | 访问后台、查看证据、修改资源                                |
| editor   | 创建和编辑资源、补充来源/授权/链接、查看自己提交的处理状态                                                | 审核或发布自己的提交、处理投诉、管理账号/权限、查看敏感证据 |
| reviewer | 审核资源、发布/隐藏/归档、处理提交/举报/侵权通知/恢复申请、维护分类标签、查看必要证据、触发链接检查和报表 | 管理管理员和角色                                            |
| admin    | reviewer 全部能力、管理员/角色/权限、系统配置、密钥引用和审计访问                                         | 不得绕过审计或将点击伪造为转化                              |

MVP 不建立普通用户账户系统。匿名历史仅在浏览器本地保存，不上传服务端。

| ---------------------- | ------: | ----------------------: | ------------------: | ----: |

| `resource.publish`     |       — |                       — |                   ✓ |     ✓ |

| `governance.handle`    |       — |                       — |                   ✓ |     ✓ |
| `analytics.read`       |       — |                       — |                   ✓ |     ✓ |
| `settings.write`       |       — |                       — | ✓（分类/标签/词库） |     ✓ |

`resource.read_public` 表示匿名公开 DTO，不表示可以读取后台字段。权限判定、资源归属判定和“不能审核自己”均在服务端执行，不能由前端按钮控制替代。

## 4. 核心用户旅程

### 4.1 访客搜索与跳转

1. 访客输入关键词并选择网盘/分类/授权类型/链接状态等筛选条件。
2. 服务端从 Meilisearch 获取候选资源 ID，再由 PostgreSQL 复核公开状态、授权有效期、投诉隐藏和链接状态。
3. 结果卡片展示标题、说明、标签、更新时间、网盘、链接状态、授权状态和操作。
4. 访客查看详情，点击 `/go/{resourceId}/{provider}`。
5. 服务端只从数据库已审核记录构造官方目标 URL，记录最小化点击事件后 302 跳转；点击不等于转化。

### 4.2 资料提交与审核

1. 访客提交标题、说明、来源、网盘链接、提取码、权利类型、许可/授权说明、联系方式和真实性声明。
2. 服务端进行 CSRF、机器人、频率、URL、字段长度和附件校验，写入 `submissions`，默认 `pending`。
3. reviewer/editor 在授权边界内补齐资源与证据；editor 不能审核自己的提交。
4. reviewer 校验权利、来源、链接和禁止内容，执行允许的状态迁移并写审计日志。
5. 只有 `approved + published + 有效权利 + 有来源 + 有有效授权依据 + 有可用链接 + 无投诉隐藏` 才可公开。

### 4.3 侵权通知与恢复

1. 公众无需登录提交侵权通知，系统生成不可枚举的公开票据号和私有工单。
2. 材料完整且可信时，事务内先将资源置为 `temporarily_hidden`，写 outbox 和审计记录。
3. reviewer/admin 在最小权限下处理证据，必要时通知提交方。
4. 结果为永久下架、维持隐藏、恢复发布或补充材料；恢复必须重新验证公开条件。

## 5. 功能需求

### 5.1 搜索首页与结果

- 首页：站点名、搜索框、管理员配置热门词、仅浏览器本地的搜索历史、热门/最近更新/分类入口、网盘筛选、合规说明、投诉入口。
- 检索字段：标题、简介、标签、分类、作者/来源；辅助字段包括中文拼音全拼和首字母。
- 支持简繁关键词、前缀、拼音、管理员同义词、受控拼写容错、搜索建议、无结果推荐。
- 筛选：网盘、分类、发布时间、授权类型、链接状态；排序：相关度、最新、热门。
- URL 可恢复关键词、筛选、排序和分页；只显示公开 DTO，不暴露提取码、证据、内部备注和账号信息。
- 1～2 字、数字、版本号、专有名词和提取码使用保守匹配，避免过度模糊召回。

### 5.2 资源详情

公开：标题、简介、封面、分类、标签、可为空的文件目录摘要/数量/大小及来源更新时间、来源说明、公开许可、更新时间、网盘/链接状态/检测时间、前往网盘、举报、相关推荐。

不公开：授权证据、联系方式、内部备注、提取码明文（除非产品确认展示且仍不进入日志/分析）、账号、Cookie、Token、推广密钥、内部接口。

### 5.3 后台与治理

- 资源新增、编辑、预览、审核、发布、隐藏、归档、软删除；已发布资源的权利/来源/链接关键修改必须重新审核或走修订版本。
- 分类、标签、同义词、热门词、推荐位、网盘链接、提取码、渠道模板、授权记录/证据、到期提醒。
- CSV 和 Markdown 导入均为“解析预览 -> 管理员确认 -> 写入”，批次有唯一幂等 ID、逐行结果和失败报告。
- 链接手工复核、检查历史、提交/举报/侵权/恢复工单、黑名单、搜索/无结果/点击/渠道/链接健康统计。
- admin 维护管理员、角色、权限；所有敏感操作写追加式审计日志。

### 5.4 合规写入条件

公开资源必须同时满足：`review_status=approved`、`publication_status=published`、权利状态为 `owned|authorized|open_licensed|public_domain`、至少一条来源、至少一条未过期授权/许可/公有领域依据、至少一条 `is_enabled=true` 且状态不为 `expired|disabled` 的链接、不属于禁止内容、不处于投诉临时隐藏，且来源/域名未命中治理黑名单。`blocked` 不作为适配器状态；平台或治理阻断统一落到 `is_enabled=false`、`disabled` 或黑名单。

## 6. 固定状态

### 6.1 资源

- `rights_status`: `owned`, `authorized`, `open_licensed`, `public_domain`, `insufficient_evidence`, `revoked`, `prohibited`
- `review_status`: `pending_review`, `needs_changes`, `approved`, `rejected`
- `publication_status`: `draft`, `published`, `temporarily_hidden`, `archived`, `deleted`
- `complaint_status`: `none`, `under_review`, `temporarily_hidden`, `restored`, `permanently_removed`

### 6.2 网盘链接

`pending`, `available`, `expired`, `need_password`, `password_error`, `risk_controlled`, `unsupported`, `unknown`, `disabled`。

### 6.3 工单

- `submission`: `pending`, `needs_info`, `approved`, `rejected`, `withdrawn`
- `report`: `open`, `triaged`, `resolved`, `dismissed`
- `takedown`: `received`, `temporarily_hidden`, `awaiting_response`, `restored`, `permanently_removed`, `closed`
- `counter_notice`: `received`, `under_review`, `accepted`, `rejected`, `closed`

状态迁移由 `packages/core` 统一实现，数据库使用枚举/检查约束；非法迁移必须返回结构化错误并审计失败。

## 7. 非功能需求与验收目标

- 安全：服务端再次校验所有输入/权限；密码 Argon2id；会话令牌只存哈希；SSRF、开放重定向、CSRF、XSS、越权和敏感信息泄露有专项测试。
- 隐私：原始搜索与点击事件默认 90 天；不保存完整 IP、浏览器指纹和完整 UA；无地区统计能力时关闭地区字段。
- 可用性：移动优先、语义化 HTML、键盘可用、焦点/错误/加载/空/风控状态明确，核心 WCAG 2.2 AA。
- 一致性：PostgreSQL 是唯一事实来源；Meilisearch 可重建；写入通过 outbox 异步同步。
- 性能目标（需在阶段四按真实环境验证）：10 万资源/20 万链接容量验证；搜索 P95 <500ms；跳转 P95 <300ms（不含网盘）；下架索引移除目标 60 秒内。
- 恢复目标：每日备份，初始 RPO 24 小时、RTO 4 小时，完成可复现恢复演练后才可宣称达成。

## 8. MVP 范围

范围内：匿名搜索/详情/安全跳转、本地授权资源库、夸克/百度/受限通用外链适配器、审核与治理、投诉/恢复、链接检查 Worker、Meilisearch、点击与官方转化分表、CSV/Markdown 导入、审计/保留/备份基础能力。

范围外：外部数据源接入、全网爬取、普通用户账号、收藏/评论/评分/私信、个性化推荐、自动转存/下载、登录后网盘检查、复杂浏览器挑战绕过、推断转化、移动原生 App。

## 9. MVP 验收场景

以 `TASKS.md` 的追踪矩阵为唯一编号来源，至少覆盖：隐藏资源不可搜索/详情/跳转；已发布关键变更需复审；中文/拼音/同义词/错别字固定评测；自有权重不压过高相关资源；链接规范化去重与 SSRF 防护；`/go` 无开放重定向；点击不生成转化且官方回调幂等；投诉下架可审计；editor 权限边界；敏感信息不泄露；事件清理；Worker/搜索故障不丢写入；空库迁移到核心流程；备份恢复。
